## 1. 适用范围

本目录用于 Windows 7 SP1、Windows 10 和 Windows 11 终端，包含现场检查修复、FTP 静默检查修复回传、违规记录清理和报告管理四类工具。正式终端程序采用 Win7 兼容的 32 位静态构建，可在 32 位和 64 位 Windows 上运行，不需要安装 .NET、Python、Java、数据库或 VC++ 运行库。

所有检查修复入口使用同一套检查标准，标准流程为：

```text
修复前检查 → 保存原始结果 → 修复允许处理的系统异常 → 修复后复检 → 生成对比报告
```

浏览器密码、USB 历史和无线网络历史属于用户数据，不由静默修复版自动删除，必须使用独立清理工具人工确认。

## 2. 目录和入口

| 目录 | 入口 | 用途 |
|---|---|---|
| `01-现场检查修复版` | `onsite-check-repair.exe` | 现场检查、确认修复、只检查和回滚 |
| `02-FTP检查修复回传版` | `ftp-check-repair.exe` | 网管静默执行并通过 FTP 回传报告 |
| `03-违规记录清理版` | `record-cleaner.exe` | 人工清理浏览器、USB 和无线违规记录 |
| `04-报告管理工具` | `ftp-report-pruner-x64.exe`、`report-person-exporter.exe` | Windows/麒麟混合报告去重和 Excel 汇总 |

每个目录均有独立 `README.md`。把某个程序交给运维人员时，应将该程序所在目录整体复制，不要只复制入口文件。

## 3. 推荐工作流程

1. 单机排查使用现场版；网管批量推送使用 FTP 版。
2. 检查报告出现浏览器保存密码、USB 历史或无线历史时，先保存报告证据。
3. 由数据所属的当前用户运行违规记录清理版。
4. 清理完成后再次运行现场版的只检查模式，生成最终复检报告。
5. Windows 和麒麟报告统一放入 Windows 接收端的同一报告目录。
6. 在报告目录先运行去重工具，再运行人员问题 Excel 汇总工具。

## 4. 检查和修复范围

自动修复范围：

- Windows 防火墙域、专用、公用配置文件。
- 10 条高危端口入站阻断规则：TCP 22、135、136、139、445、3389；UDP 136、137、138、3389。
- 停止并禁用 `LanmanServer`（Server 文件共享服务）。
- 停止并禁用 `TermService`，并拒绝远程桌面连接。
- 在全部可配置网卡上禁用 NetBIOS over TCP/IP。

明确不会执行：

- 不停止 RPC/RpcSs。
- 不添加出站阻断规则。
- 不自动重启。
- 不绕过域策略、安全软件或管理平台策略。
- 不自动删除浏览器密码、USB 历史或无线历史。
- 不停止已识别的 FTP 接收服务，也不删除第三方 FTP 允许规则。

如果终端承担 FTP 扫描接收业务，程序会检查控制端口、有限被动端口、允许来源和防火墙规则；证据不完整时标记“需复核”，不会擅自开放未知端口。正式批量推送前必须在真实扫描终端上验证控制连接、认证、数据连接和文件落盘。

浏览器检查覆盖 Chromium 系浏览器、Firefox，以及 Internet Explorer 的 Windows Web Credentials、旧版 Storage2 和 WinInet 凭据索引。程序只读取条目数量、网站和账号元数据，不读取或解密密码；SYSTEM 无法代表登录用户读取 IE 凭据时会标记“需复核”，不会误判为“通过”。

## 5. 报告

检查报告统一命名：

```text
verification-report_<IP>_<MAC>_<时间戳>.html
verification-report_<IP>_<MAC>_<时间戳>.json
```

HTML 供人工查看，JSON 供报告管理工具读取。报告包含修复前检查、修复动作和修复后复检；JSON 顶层 `summary` 和 `details` 表示最终状态。

报告可能包含终端标识、账号名、浏览器保存登录的网站和账号元数据，应按内部安全检查资料保管。程序不会读取或输出密码明文、Cookie 或令牌。

## 6. 备份和回滚

首次修复前状态保存到：

```text
%ProgramData%\SecurityRemediator\backup-v2.state
```

重复运行不会覆盖有效的首次备份。现场版 `/rollback` 只恢复本程序管理的系统配置，不恢复已经人工删除的浏览器、USB 或无线记录。

## 7. 部署与验收

- 现场版和清理版应由已提权管理员运行；清理版必须以数据所属的当前用户运行，不能由 SYSTEM 代替。
- FTP 版可以由网管系统以 SYSTEM 或已提权管理员身份运行。
- 批量部署前先执行小范围灰度，并核对 HTML、JSON、上传状态和退出码。
- 高危端口是否能从外部访问，必须从另一台电脑探测；本机“未监听”或“有阻断规则”不能替代外部验证。
- 域策略或安全软件可能在运行后重新覆盖设置，必要时应在策略刷新或重启后复检。
