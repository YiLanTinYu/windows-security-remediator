# 银河麒麟版终端安全检查与修复工具

版权所有人：倚栏听雨
许可和使用边界见各目录中的 `COPYRIGHT.txt`。

## 1. 适用范围

本目录用于银河麒麟桌面操作系统 V10 SP1，提供 x86_64（amd64）和 ARM64 两种架构的单文件程序。客户端无需安装 Go、Python、Java、数据库、浏览器驱动或其他运行库，不安装 systemd 服务、不创建开机启动项、不常驻后台，也不使用 SSH 远程登录。

## 2. 目录

| 目录 | 用途 |
|---|---|
| `客户端` | 只读检查、现场修复、FTP 检查修复回传和违规记录清理 |
| `接收端` | 可选的 Windows FTP 接收端启动包；当前生产环境也可以直接使用既有 Windows 接收端 |

当前统一管理方案是：Windows 与麒麟客户端都把报告上传到同一个 Windows FTP 接收目录，再由 Windows 版“报告管理工具”统一去重、匹配人员和生成 Excel，不开发独立的麒麟报告管理程序。

## 3. 客户端入口

在 `客户端` 目录运行：

| 脚本/程序 | 行为 |
|---|---|
| `Run-Audit.sh` | 只读检查，不修改系统 |
| `Run-Repair.sh` | 修复前检查、修复、即时复检 |
| `Run-FTP.sh` | 修复前检查、修复、复检并通过 FTP 回传 |
| `kylin-cleaner-amd64/arm64` | 人工清理浏览器、无线和允许安全清理的 USB 用户记录 |

脚本会自动识别 CPU 架构。完整命令、必需文件、输出和退出码见 `客户端/README.md`。

## 4. 检查和修复范围

- 高危端口入站防护。
- SSH、Samba 服务端和已识别的远程桌面服务。
- 无线网卡和 NetworkManager 保存配置。
- USB 当前设备、块设备、挂载、内核日志和用户级最近文件线索。
- Chromium 系浏览器及可识别的保存登录记录。

检测到 CEMS/KSC 接管 `INPUT` 时，程序只审计 CEMS 通用策略是否覆盖目标端口，不抢占规则顺序、不改写 CEMS/KSC 链，也不把后置无效规则报告为成功。CEMS 已覆盖的项目显示正常；未覆盖的项目列为“管理端待补”，应在 CEMS 管理端处理并通过外部端口探测验收。

非 CEMS 环境才由本程序维护自己的高危端口阻断链。修复可能停止并禁用 SSH、Samba 和远程桌面服务，也可能关闭无线功能；运行前必须确认终端通过有线网络或其他不受影响的管理通道连接。

## 5. 报告和统一管理

正式检查报告统一命名：

```text
verification-report_<IP>_<MAC>_<时间戳>.html
verification-report_<IP>_<MAC>_<时间戳>.json
```

FTP 上传状态文件：

```text
upload-status_<IP>_<MAC>_<时间戳>.json
```

HTML/JSON 使用与 Windows 报告一致的阅读和管理结构，JSON 中 `platform` 为 `Kylin`。把报告放入 Windows 报告目录后，使用 Windows 版 `04-报告管理工具` 处理。

报告可能包含终端账号、浏览器保存登录的网站和账号元数据，应按内部检查资料保管；不包含密码明文、Cookie、令牌或 FTP 密码。

## 6. 验收要求

- x86_64 和 ARM64 分别在至少一台真实麒麟终端上验证。
- 检查 HTML/JSON 是否成对生成，IP/MAC 和平台信息是否正确。
- 修复后立即复检，并在重启或 CEMS/KSC 策略刷新后再次复检。
- 从另一台电脑探测高危入站端口；本机 iptables 输出不能代替外部验证。
- FTP 版同时检查本地报告、上传状态和 Windows 接收目录中的最终文件。
- 只有部分终端 FTP 失败时，应比较路由、ARP、CEMS/防火墙、VLAN 和交换机访问控制，不要直接判断为架构或程序故障。
