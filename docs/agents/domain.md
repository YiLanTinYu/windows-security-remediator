# Domain Docs

This repository uses a single-context domain documentation layout.

## Before exploring

- Read `CONTEXT.md` at the repository root when it exists.
- Read ADRs under `docs/adr/` that affect the area being changed.
- If these files do not exist, proceed silently; domain-modeling work creates them when decisions are actually resolved.

## Vocabulary

Use the terms defined in `CONTEXT.md` in issues, proposals, tests, and code. If a required concept is missing, reconsider whether new terminology is necessary or record the gap for domain modeling.

## ADR conflicts

If a proposed change contradicts an existing ADR, surface the conflict explicitly instead of silently overriding the decision.
