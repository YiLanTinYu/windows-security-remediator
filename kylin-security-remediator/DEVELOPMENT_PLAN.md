# 银河麒麟终端安全检查与修复工具开发计划

## 1. 文档状态

- 状态：已确认，开发必须按本文档执行。
- 目标系统：银河麒麟桌面操作系统 V10 SP1，已知实机版本 `KYLIN_RELEASE_ID=2403`。
- CPU 架构：`x86_64/amd64`、`ARM64/aarch64`。
- 首次确认的防火墙环境：`iptables 1.8.4`，存在 CEMS 与 Kylin Security Center 管理的 `CEMS_*`、`KSC_*` 规则链。
- SSH：终端不使用 SSH；不开放 10222，修复时停止并禁用 SSH 服务并阻断 TCP 22。
- 版本控制：未经用户明确指示，不提交、不推送、不上传 GitHub。

### 1.1 银河麒麟无人值守推送状态（2026-09-15）

- 状态：**暂停开发，后续条件具备时可重启**。
- 暂停范围仅限“通过现有网管系统向银河麒麟终端无人值守分发并启动程序”；现场版、FTP版、记录清理版、报告接收端及两种CPU架构成品继续保留和测试。
- 暂停原因：现有网管软件分发界面使用Windows专用`CSIDL_*`下载目录，不能区分Windows与银河麒麟，也不能区分麒麟`x86_64`与`ARM64`；实测`.sh`探针未在麒麟终端落地，当前没有可验证的Linux文件分发和执行通道。
- 当前结论：不得把Windows软件分发模块假定为银河麒麟推送通道，不继续开发依赖该通道的自动架构选择、自解包或无人值守启动功能。
- 已完成成果继续保留：linux/amd64与linux/arm64静态单文件、运行时FTP参数、Windows单文件FTP接收端、现场运行流程及实机测试记录。
- 重启开发前置条件：网管厂商或其他经授权平台提供可验证的Linux文件下发和命令执行能力，能够以root身份运行、传递运行参数或安全凭据，并能识别终端操作系统与CPU架构，或至少能够按单台终端精确指定任务和返回执行状态。
- 若前置条件满足，先使用无修改探针验证分发、执行身份、架构识别和结果回传，再恢复正式程序的无人值守推送开发。

## 2. 总体目标

交付现场版、FTP 静默回传版和记录清理版。三者必须复用同一检查核心、同一修复核心和同一报告模型。分别生成 amd64 与 arm64 成品，不要求服务端或客户端安装 Python、Java、.NET、数据库、浏览器驱动或其他运行库。

默认流程：

1. 修复前检查。
2. 备份本程序将修改的状态。
3. 执行系统修复。
4. 修复后复检。
5. 生成 HTML 与 JSON 对比报告。
6. FTP 版使用被动模式上传；失败时保留本地报告。

## 3. 交付物

| 交付物 | amd64 | arm64 | 行为 |
|---|---|---|---|
| 现场检查修复版 | `kylin-onsite-amd64` | `kylin-onsite-arm64` | 有控制台提示，确认后修复，默认打开或提示报告位置 |
| FTP 静默版 | `kylin-ftp-amd64` | `kylin-ftp-arm64` | 无交互，检查、修复、复检、保存并回传 |
| 记录清理版 | `kylin-cleaner-amd64` | `kylin-cleaner-arm64` | 清理浏览器登录记录、无线配置和允许安全清理的 USB 用户级痕迹 |
| FTP 报告接收服务 | `report-receiver-windows-amd64.exe` | 可选 Linux 成品 | 单文件运行，本地目录保存，不依赖数据库 |

## 4. 技术栈与无依赖边界

- 语言：Go，锁定项目工具链版本并保留可复现构建说明。
- 构建：`CGO_ENABLED=0`，目标为 `linux/amd64`、`linux/arm64`。
- 报告：Go 标准库生成 UTF-8 HTML 与 JSON。
- FTP：程序内置被动 FTP 客户端；不调用 `curl`、`ftp` 等外部客户端。
- 浏览器数据库：使用静态编入程序的纯 Go SQLite 实现；不依赖系统 `sqlite3`。
- 操作系统接口：允许使用银河麒麟自带的 `iptables`、`systemctl`、NetworkManager/`nmcli`、`journalctl`。这些属于目标系统能力，不要求额外安装。
- 程序必须在缺少任一系统能力时返回“数据源不可用”，不得把它误报为“未发现记录”或“已修复”。

## 5. 统一检查与修复范围

### 5.1 终端身份

采集主机名、系统版本、内核、CPU 架构、实际桌面用户、执行用户、IP、MAC、有线/无线网卡和执行时间。报告文件名包含 IP、MAC 和毫秒级时间戳。

### 5.2 防火墙和高危端口

检查并阻断入站：TCP 22、TCP 135、TCP/UDP 136、UDP 137、UDP 138、TCP 139、TCP 445、TCP/UDP 3389。

- 检测到`INPUT`跳转到`CEMS_COMMON_INPUT`时，进入CEMS协同模式：只审计10项目标端口在CEMS链中的首个有效`ACCEPT/DROP/REJECT`判决，不执行本地iptables修复。
- CEMS未覆盖项逐项报告为“CEMS管理端待补”，由管理员在CEMS策略中补充；不得通过抢占`INPUT`首位或写入`CEMS_*`链绕过管理端。
- 当前实机快照识别为CEMS已覆盖6项，管理端待补`TCP 136`、`TCP 445`、`UDP 136`、`UDP 3389`；程序按当次规则动态判断，不硬编码这一结果。
- 未检测到CEMS接管时，创建并只管理 `SEC_REMEDIATOR_INPUT` 独立链。
- 不清空、不删除、不改写 `CEMS_*`、`KSC_*` 或其他第三方规则。
- 重复执行不新增重复规则。
- 非CEMS环境修改后验证链的实际挂载顺序和目标端口的有效判决。
- 未识别为CEMS协同模式但规则仍被其他安全策略覆盖时，报告“安全策略覆盖”，不循环争抢。
- 保存变更前快照；回滚只恢复本程序实际修改的状态。
- 不安装 systemd 服务、不设置开机启动、不常驻后台；CEMS环境由管理端保持策略，非CEMS本地规则只保证本次运行后的即时复检状态。

### 5.3 服务

- SSH：停止并禁用 `ssh`/`sshd`，阻断 TCP 22；不删除软件和配置。
- 文件共享：识别并停止、禁用 `smbd`、`nmbd`、`samba` 等服务器服务，不影响访问外部 SMB 服务的客户端能力。
- 远程桌面：识别并停止、禁用 `xrdp`、常见 VNC 与桌面共享服务；未知自定义服务只报告。

### 5.4 无线网络

- 识别无线网卡、无线功能状态、当前连接和 NetworkManager 保存配置。
- 删除明确为 Wi-Fi 或手机热点的历史配置。
- 有线配置不处理；类型不明的配置列出供人工确认。
- 当前正在依赖 Wi-Fi 联网时拒绝自动删除当前连接并标记需复核。
- 按有线终端策略关闭无线功能；回滚可恢复修改前状态。

### 5.5 USB 存储设备

综合 `/sys`、udev 数据、内核/系统日志、挂载记录和用户级最近记录。状态必须严格区分：找到记录、确定无记录、权限不足、数据源不存在、日志已轮换、解析失败。

清理仅限用户级缓存、最近挂载记录及能够独立、安全识别的设备缓存。禁止通过删除整个 journal、syslog 或审计日志制造“0 条记录”。无法安全单独清理的证据保留并在临时报告中说明。

### 5.6 浏览器保存密码

- 支持 Chromium、Chrome、Edge、Firefox、银河麒麟浏览器及通过特征识别的 Chromium 衍生浏览器。
- 只有数据库中存在有效登录条目时才判定“保存了密码”；配置目录或数据库文件存在不能作为违规依据。
- 报告浏览器、用户配置、网站地址和账号；不读取、显示或上传密码明文、Cookie、令牌。
- Firefox 或系统密钥环导致账号不可读取时，显示网站、条目数和限制原因，不猜测账号。
- 浏览器运行导致数据库锁定时复制到私有临时目录只读检查，结束后删除临时副本。
- 清理只删除保存的登录凭据，不处理 Cookie、浏览历史、收藏夹、扩展或当前登录会话。

## 6. FTP 回传

- 使用被动 FTP：终端主动连接控制端口及服务端返回的被动数据端口，服务端不反向连接终端。
- 地址、端口、用户名和密码不得写入公开源码、README、报告或日志。
- 正式配置通过简单启动参数或私有构建配置注入；无有效配置时只保存本地报告。
- 普通 FTP 不加密，部署时必须使用仅上传账号、限制来源 IP 和上传目录权限。
- 上传 HTML 和 JSON；最多三次有限重试；不得无限后台运行。
- 退出状态和本地上传状态文件必须区分检查异常、修复失败和上传失败。

## 7. 报告和结论

HTML 与 JSON 共享同一结果对象，顺序固定为：终端信息、修复前汇总、防火墙、服务、网络/无线、USB、浏览器登录、执行动作、修复后汇总、总体结论。

每项包含检查项目、预期结果、实际结果、结论、处理情况和证据来源。颜色固定：通过绿色、异常红色、需复核黄色、不适用灰色。现场版与 FTP 版对同一系统快照产生的业务结果必须逐项一致。

## 8. TDD 公共测试缝（已作为本计划的一部分确认）

5. FTP：给定本地测试服务，验证被动上传、重试、失败保留和文件完整性。

## 10. 虚拟测试流程

1. 纯逻辑单元测试和竞争检测。
2. 用已采集的 CEMS/KSC 规则制作脱敏 fixture，验证有效路径、规则顺序和不修改第三方链。
3. 在隔离 Linux 虚拟机/网络命名空间测试真实 iptables；不得在开发主机直接改防火墙。
4. 使用临时 systemd/命令 fixture 测试服务不存在、停止、运行、禁用和失败。
5. 使用临时 NetworkManager配置测试有线、Wi-Fi、热点、当前无线和未知类型。
6. 使用合成 sysfs/udev/journal fixture 测试 USB 六种状态。
7. 使用不含真实用户数据的 Chromium/Firefox数据库测试检测和清理。
8. 使用本地隔离FTP服务测试被动上传、重试、断线、重复报告和校验和。
9. 构建 linux/amd64 与 linux/arm64，检查文件格式、动态依赖和内置敏感字符串。
10. 虚拟测试结果仅作为进入实机测试的门槛，不替代实机验收。

## 11. 实机验收清单

两种架构分别执行：

- 无附加安装情况下启动、报告和退出码。
- 普通用户权限不足、root/网管代理正常运行。
- KYSEC/CEMS允许、阻止和刷新策略后的行为；策略覆盖时只报告，不循环争抢。
- 重启后确认没有本程序新增的服务、启动项或监听端口；再次推送后能够重新检查和修复。
- 原有 CEMS/KSC 规则数量、内容和顺序不被修改。
- 目标端口从另一台电脑逐项探测；FTP上传不被自身规则阻断。
- SSH服务停止且禁用，22不可连接，没有新增10222监听。
- Samba、xrdp/VNC在已安装和未安装场景的判断与修复。
- 客户端访问外部文件服务器不受影响。
- 无无线网卡、无线网卡禁用、多个Wi-Fi/热点、当前Wi-Fi和未知配置。
- 从未接入USB、插拔U盘、移动硬盘、手机存储和非存储USB；日志轮换与权限不足。
- 浏览器未安装、空密码库、一个测试账号、删除后复检、多用户、多配置、运行锁定、Firefox主密码和一种非主流浏览器。
- FTP正确配置、临时配置、错误地址/端口/凭据、服务器不可达和上传中断。
- 连续运行三次不重复规则、不产生不同业务结论。
- 回滚只恢复本程序改动，不破坏测试期间的外部变更。
